# 智能语音聊天机器人设计与实现-项目事实冻结

## 事实冻结原则

- 学校模板优先于其他非代码材料。
- 项目事实以当前源码为准，优先级高于历史论文、旧说明文档与演示材料。
- 本文只冻结“已经在代码中真实存在或可以被当前资产佐证”的内容。
- 下列内容禁止写入正文：`OCR` 主流程、通用图像识别主流程、复杂多角色权限系统、虚构实验数据、虚构性能结论、真实密钥与环境变量。

## 项目定位

本项目是一个面向中文场景的多模态智能语音对话系统。系统不只是普通的“聊天页 + 大模型接口调用”，而是围绕统一会话运行时组织文本对话、语音输入、实时语音通话、知识库增强、上下文记忆、Provider 与模型管理、链路配置、人格配置、音色配置与图片生成等能力的全栈应用。

论文统一口径如下：

1. 重点是统一会话运行时、双语音策略、RAG 增强与实时中断交互。
2. 重点不是“页面很多”，而是“前后端如何协同维持一套统一会话框架”。
3. 详细设计部分围绕真实模块、真实截图、真实代码片段展开。

## 系统架构

### 总体分层

系统整体可分为四层：

1. 表现层：前端页面与交互组件。
2. 会话运行时层：`SessionRuntime` 统一管理文本与语音事件、状态转换、轮次指标与策略切换。
3. 服务编排层：后端负责消息处理、检索增强、Provider 路由、语音链路、实时通话与系统配置。
4. 数据与配置层：`PostgreSQL + pgvector` 保存会话、消息、记忆、知识库、链路配置、音色配置和审计数据。

## 核心设计点

### 统一会话运行时

前端通过 `SessionRuntime` 统一管理以下内容：

1. 会话标识与模式切换。
2. 文本与语音事件。
3. 用户转写与助手增量回复。
4. 轮次性能指标。
5. 当前链路状态、打断与恢复。

对应依据：

- `frontend/src/runtime/voice/sessionRuntime.ts`

### 双语音策略

系统支持两种语音策略：

1. `integrated-realtime`
   - WebSocket 持续上传音频块。
   - 支持本地 VAD、自动打断和实时语音状态切换。
   - 更强调实时连续交互体验。
2. `split-chain`
   - 优先使用浏览器 ASR，失败时回退到后端 ASR。
   - 采用分阶段语音识别与文本提交机制。
   - 更强调链路拆分、可控性和可替换性。

对应依据：

- `frontend/src/runtime/voice/integratedStrategy.ts`
- `frontend/src/runtime/voice/splitStrategy.ts`

### 实时语音通话

后端 WebSocket 实时通话模块具备以下真实行为：

1. 接收音频块并进行局部语音识别。
2. 在提交时进行最终转写。
3. 触发检索增强与回复生成。
4. 返回助手文本、音频与轮次指标。
5. 处理空提交、重复提交、打断与取消。

对应依据：

- `backend/app/modules/realtime_ws/router.py`

### RAG 检索增强

知识增强流程真实包含：

1. 文档解析。
2. 文本切块。
3. 向量化。
4. 相似度召回。
5. 重排序。
6. 基于检索门控的上下文注入。

对应依据：

- `backend/app/modules/knowledge_rag/router.py`
- `backend/app/modules/chat/service.py`
- `backend/app/modules/chat/langchain_pipeline.py`

### Provider 与模型路由

系统支持多 Provider 配置，并通过模型目录、调用配置和链路配置控制实际调用路径，默认涉及：

- `dashscope`
- `volcengine`
- `siliconflow`

对应依据：

- `backend/app/main.py`
- `backend/app/core/provider_gateway.py`
- `backend/app/modules/chat/engine.py`

3. 将图片生成功能写成核心主链路创新点。
4. 将语音链路写成单一 ASR/TTS 串接。
5. 将知识库写成“只有向量检索”的简单流程。
6. 编造未在测试中出现的定量性能结论。
