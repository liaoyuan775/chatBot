# 单租户试运行部署说明

## 目标

本文档面向单一院校、实验室或单位内部试运行场景，目标是让系统在单机或单节点环境中稳定部署，并具备最小管理员登录、运行诊断、审计追踪与回退说明能力。

## 环境准备

1. 准备 PostgreSQL 数据库，并创建白名单中的数据库名。
2. 准备至少一个可用的模型服务 API Key，例如 DashScope 或 SiliconFlow。
3. 复制 `.env.docker.example` 为 `.env.docker`，按实际环境填写。

关键环境变量：

- `APP_ENCRYPTION_KEY`：必须替换为长随机串。
- `ADMIN_USERNAME` / `ADMIN_PASSWORD`：管理端默认管理员账号。
- `AUTH_COOKIE_SECURE`：生产环境建议为 `true`，仅 HTTPS 传输。
- `ALLOWED_DATABASES`：限制后端只连接受信数据库。
- `DASHSCOPE_API_KEY` / `SILICONFLOW_API_KEY`：按实际供应商填写。

## 首次启动

1. 启动数据库。
2. 启动后端服务，系统会自动创建业务表、管理员表与审计表，并补齐默认管理员。
3. 启动前端服务。
4. 访问 `/login`，使用管理员账号登录管理端。
5. 进入“厂商与模型”页面配置 provider，再进入“系统配置”查看诊断状态。

## 运行诊断

管理端“系统配置”页会聚合：

- 数据库连接状态
- Provider 健康概览
- 最近链路失败摘要
- 审计日志
- 当前系统配置快照

后端接口：

- `/healthz`：基础存活检查
- `/readyz`：就绪检查
- `/api/admin/ops/diagnostics`：受保护的运行诊断接口

## 故障降级说明

- RAG 超时：直接跳过检索，继续生成主回复。
- Provider 调用失败：按既有 fallback 顺序切换备用模型或备用 TTS。
- TTS 失败：保留文本回复，不阻断对话完成。
- 实时链某一分支异常：保留同类链路内部回退与统一错误痕迹。

## 备份建议

建议至少定期备份以下数据：

- 会话与消息表
- 知识库文档与向量元数据
- Provider / 模型 / 链路 / 系统设置
- 管理员审计日志

## 交付验收建议

推荐按以下路径演示：

1. 管理员登录
2. 配置 Provider 并验证连通性
3. 上传知识库文档
4. 发起文本问答与实时语音问答
5. 查看系统配置页中的诊断信息与审计日志
